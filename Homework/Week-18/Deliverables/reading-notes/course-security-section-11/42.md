what is an service account
- for non-human things like apps, services

if an user wants to interact with gcp services we use username and passwords

if an application wants to interact with gcp services the app uses service accounts

both username/password and service accounts are methods of authentication

service accounts in the context of vm'S
- we have an vm within google cloud
- the service account is the identity for the vm which allows for api calls like uploads and downloads

the service account is like an identity for your compute engine

service account keys are for authentication

how an service account authenticates that it is an real user, and if has sufficent privileges to interact with those gcp resources

with each service account one can generate keys and this key can be used for authentication purposes

you can create max 10 keys per service account

you can delete the keys

per project you can create max 100 service accounts per project

types of service accounts
- google managed service account - automaticaly created by google. these are used by google for vm updates or patching of database, or any kind of background task like a vm migration from one drone to another drone - also this erivce account is managed by google
- built in service account - are an identity for gcp services like compute engine, app engine - when you enable an api for these service and default service account gets created - this type of service account can always get associated with things like compute engine instances or app engine - once said service accounts gets asscoiated with compute engine through compute engine anything you can do, or your perosnal id is not accountable for what the compute egnine will do - everything is the responsability of the service account
- user created service account - completly under an users control
